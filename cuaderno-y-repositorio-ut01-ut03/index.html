Cuaderno y repositorio: lo que tienes que tener (UT1 – UT3)

Esta página reúne todo lo que debe haber en tu cuaderno y en tu repositorio de GitHub al terminar las tres primeras unidades. Úsala como lista de comprobación: marca cada casilla cuando la tengas hecha.

Leyenda: ⭐ es opcional · 💾 va en el repositorio.

1. Normas generales

El cuaderno

  • Es un cuaderno físico, solo para DWES. No vale un documento en el ordenador.
  • Escribe tu nombre y la fecha en cada página.
  • Encabeza cada tarea con la unidad y la actividad, por ejemplo: «UT3 · P05 · Traza del triángulo».
  • Escribe con bolígrafo. Cuando compruebes algo con el ordenador, corrige en rojo, sin tachar lo que hiciste antes: el error también cuenta como aprendizaje.
  • Lo que se hace «antes de programar» o «antes de ejecutar» se hace de verdad antes. Se nota.
  • Para entregar, fotografía o escanea las páginas y súbelas a Moodle en un único PDF. Si una foto no se lee, esa parte se califica con 0.

El repositorio

  • Tiene que existir un solo repositorio para todo el módulo. Dentro debe haber una carpeta por unidad.
  • El repositorio es privado, invita al profesor como colaborador.
  • Haz un commit por práctica terminada (o por trozo, cuando la actividad lo pida), con un mensaje que diga qué has hecho: P04: ficha de datos, C02: función euros().
  • Haz git push al terminar cada sesión. Lo que no está en GitHub no existe.
  • Pega el enlace a tu repositorio en el comentario de cada entrega de Moodle.

Estructura del repositorio

Al terminar la UT3, tu repositorio debe tener esta forma:

dwes-apellido-nombre/
├── README.md                 ← tu nombre, el módulo y el curso
├── .gitignore                ← .DS_Store, .idea/, .vscode/…
├── ut01/
│   ├── README.md             ← respuestas escritas de las actividades de la UT1
│   ├── info.php
│   ├── comparativa.php
│   └── ut01p01.php
├── ut02/
│   ├── ut02p01.php … ut02p10.php
│   └── ticket.php
└── ut03/
    ├── .gitignore            ← evita que se suban las imágenes de la C03
    ├── datos.php
    ├── ut03p01.html
    ├── ut03p01-res.php
    ├── ut03p02.php
    ├── ut03p02-res.php
    ├── ut03p03.php … ut03p13.php   (con sus -res.php cuando los haya)
    ├── ut03c02.php
    ├── ut03c03.php
    ├── ut03c04.php           ← opcional
    └── uploads/
        └── .gitkeep

Órdenes de Git que vas a usar

git status                          # qué ha cambiado
git add ut02/ut02p04.php            # prepara un fichero
git commit -m "P04: ficha de datos" # guarda el cambio con un mensaje
git push                            # súbelo a GitHub
git log --oneline                   # historial resumido
git log --oneline > git-log.txt     # historial en un fichero (lo piden la C02 y la C03)

2. UT1 · Arquitectura y Desarrollo Web

Cuaderno

Práctica de aula · Peticiones y respuestas HTTP con httpbin (RA1 – CE a), c) · 30 min)

  • 1.1. URL completa de la petición GET /get y método HTTP empleado.
  • 1.2. Valor de headers → User-Agent y de origin en la respuesta JSON.
  • 1.3. Diagrama del flujo: cliente (navegador) → petición GET → servidor (httpbin) → respuesta 200 OK.
  • 2.1. Content-Type de la petición POST /post que has enviado.
  • 2.2. Parámetro del JSON de respuesta (data, form o json) en el que aparecen tus datos.
  • 2.3. Diferencia entre enviar datos por GET y por POST, en dos líneas.
  • 3.1. Tabla de códigos de estado 200, 404 y 500 completa: categoría y qué le indica al desarrollador.
  • 3.2. Nombre del código especial que devuelve /status/418.

Repositorio

  • 💾 Repositorio creado, clonado en tu carpeta de Herd o Lerd, con README.md y .gitignore en la raíz.
  • 💾 ut01/info.php con phpinfo().
  • 💾 ut01/comparativa.php: página con la fecha y la hora generadas en el servidor.
  • 💾 ut01/ut01p01.php: práctica P01 · Postman y peticiones HTTP.
  • 💾 ut01/README.md con las respuestas escritas:
    • Cabeceras Content-Type, Server, Date, Host, User-Agent y Accept de una página real y de tu servidor local, y sus diferencias.
    • Versión de PHP, Server API, fichero php.ini cargado y si están activas las extensiones cURL y PDO (datos de phpinfo()).
    • Por qué la etiqueta <?php … ?> de comparativa.php no aparece en el código fuente que recibe el navegador.
  • 💾 Commits mínimos: UT1: estructura inicial del repositorio, UT1: phpinfo y comparativa, UT1 P01: Postman.

4. UT3 · Sintaxis Avanzada de PHP

Cuaderno

Boletín de prácticas

  • P03 · Letra del DNI. Cálculo a mano para tu propio DNI: resto de la división entre 23 y letra que sale.
  • P05 · Triángulo. Traza de los dos bucles para una altura de 3: valores de $i y $j en cada vuelta y lo que se añade a la fila.
  • P10 · Presupuestos. Qué ocurre al llamar a calcularPresupuesto(500) y a calcularPresupuesto("500") con strict_types activado.
  • P11 · Calificaciones. Tu propuesta para el caso de dos alumnos con el mismo nombre.

Ejercicio de Clase 01 · Tabla Entrada – Proceso – Salida (en clase, sin ordenador)

  • Parte A. Números del 1 al 12, cada uno con una E, una P o una S.
  • Parte B. Enunciados subrayados y una tabla E-P-S por ejercicio.
  • Parte C. Tabla del enunciado incompleto, con un ? en cada hueco, y tres preguntas para el profesor.

Ejercicio de Clase 03 · Subida de ficheros: galería de fotos

  • Parte 1.1. Diagrama del viaje del fichero, con el punto en el que desaparece el fichero temporal.
  • Parte 1.2. Decisión razonada para las preguntas a), b), c) y d).
  • Parte 1.3. Las cuatro comprobaciones ordenadas, con el dato de $_FILES o la función que necesita cada una y el porqué del orden.
  • Parte 2. Tabla con el resultado de los cinco experimentos.
  • Parte 5. Tabla de pruebas con Esperado (antes de ejecutar) y Obtenido.
  • Parte 5. Si algún caso dio ✘: qué fallaba y cómo lo has corregido.
  • ⭐ Ampliación. Por qué aparece el error al superar post_max_size.
  • ⭐ Para pensar. Por qué se repite la subida al pulsar F5.

Ejercicio de Clase 04 · Tabla E-P-S de nivel medio: reserva de pistas (en clase, sin ordenador)

  • 📷 Parte A1. Enunciado subrayado con tres estilos: datos, condiciones y lo que hay que mostrar.
  • 📷 Parte A2. Tabla E-P-S, con el Proceso ordenado: primero validar cada dato, después las condiciones combinadas y al final calcular.
  • 📷 Parte A3. Salida exacta esperada para los tres envíos de prueba.
  • 📷 Parte B. Tabla del compañero corregida, con los 7 errores numerados y explicados.

El .gitignore de la C03 

uploads/*
!uploads/.gitkeep
La primera línea ignora todo lo que hay en uploads/; la segunda hace una excepción con .gitkeep para que la carpeta exista en el repositorio aunque esté vacía.

6. Antes de cerrar la 1.ª evaluación

  • Todas las páginas del cuaderno tienen nombre, fecha y la etiqueta de la actividad.
  • Las tablas Esperado / Obtenido tienen la columna Esperado rellena con bolígrafo, no copiada después.
  • git status dice nothing to commit, working tree clean.
  • git log --oneline muestra un commit por práctica y uno por trozo en la C02, la C03 y la C04.
  • Has hecho git push y en GitHub se ven las carpetas ut01/, ut02/ y ut03/ con todos los ficheros.
  • El repositorio no contiene imágenes subidas, ficheros .DS_Store ni carpetas del editor.
